# Приложение для диктофона AIREC — что делаем

## Зачем
Родное приложение AIREC (iPhone) расшифровывает неплохо, но:
- интерфейс перегружен: даты дважды, секунды, непонятные значки, два разных экрана со списком записей;
- расшифровку нужно запускать вручную для каждой записи;
- расшифровка в облаке производителя, с месячным лимитом минут и платной подпиской;
- лишние экраны (чат «AI assistant»).

Делаем своё простое приложение для iPhone 17 Pro Max (USB-C), которое работает как транскрибатор встреч.

## Главное для пользователя
1. **Расшифровка с делением по спикерам** (кто что сказал).
2. **Кратко** — короткое содержание встречи.
3. **Протокол** — бриф встречи, принятые решения, поручения и задачи (кто / что / срок).
4. **Выгрузка в PDF** по шаблону пользователя: [SUMMARY_TEMPLATE.md](SUMMARY_TEMPLATE.md)
   (резюме → темы с таймкодами → договорённости → задачи (ответственный, срок) → контекст → карточка записи →
   полный текст по спикерам).

## Как должно выглядеть
- **Один список записей.** У записи: понятное название (ИИ придумывает по содержанию), «Сегодня, 16:17 · 17 мин», первая строка текста. Без лишних значков.
- **Экран записи:** плеер (play, ±10 с, скорость) и три вкладки: **Текст** (по спикерам) · **Кратко** · **Протокол**. Кнопка «Копировать / Поделиться».
- **Всё само:** подключил диктофон → записи скачались → расшифровались → появились «Кратко» и «Протокол».
- Минимум вкладок: список записей + настройки.

## Что есть в AIREC и может пригодиться позже
- Управление записью с телефона (старт / пауза / стоп), расшифровка на лету — нужен Bluetooth-протокол.
- Флажки (отметить важный момент) и фото к записи.
- Отпечатки голоса (узнавать постоянных собеседников по голосу).
- Mind map, главы (chapters), чат с ИИ по записи, экспорт.
- Синхронизация часов диктофона (сейчас на диктофоне неверное время).

## Что уже известно (см. RESEARCH.md)
- Диктофон по USB — флешка, записи `RECORD/*.ops` = сырой Opus 16 кГц. Конвертер есть: `tools/ops2wav.py`.
- Whisper large-v3-turbo на Mac расшифровывает чистую речь почти без ошибок (17 с записи за 3 с) — не хуже AIREC.
- Bluetooth: найден сервис `0011200a-…` с 5 характеристиками, команды неизвестны → нужен разбор Android APK.

## Статус прототипа (2026-11-21)
`tools/meeting.py`: .ops → Whisper large-v3-turbo → спикеры (sherpa-onnx) → локальный Qwen 3.5 9B → PDF по шаблону.
Минута записи на M5 16 ГБ: текст ~5 с, спикеры ~6 с, протокол ~40 с.
Тест на диктовке «итоги встречи» (56 с): решения, задачи, ответственные и сроки извлечены верно.
Замечания:
- **Диктофон теряет первые ~2–4 с** после нажатия кнопки → советовать пользователям ждать пару секунд;
  Whisper на этом куске галлюцинирует («Продолжение следует…»).
- Whisper иногда не ставит точки и искажает слова («она» вместо «Анна»).
- Qwen 9B иногда добавляет лишние детали в задачи и не замечает ошибок распознавания — проверить облачный Qwen 3.6.
- Деление по спикерам проверено только на одном голосе — нужна запись разговора 2–3 человек.

## План
1. **Прототип на Mac** — одна команда: записи с диктофона → текст по спикерам → «Кратко» и «Протокол».
   Цель — проверить качество на настоящей встрече, прежде чем строить приложение.
2. **Приложение для iPhone (первая версия)** — записи забираются по кабелю USB-C; список + экран записи с тремя вкладками.
3. **Bluetooth** — разбор Android-версии AIREC: скачивание записей без кабеля, управление записью с телефона.
4. **Дополнительно** — то, что из списка «может пригодиться».

## Режим расшифровки — выбор в настройках
- **На телефоне:** модель Whisper скачивается на iPhone один раз (~1–1.5 ГБ), дальше бесплатно, без интернета,
  записи никуда не уходят. Медленнее, телефон греется. Кандидаты: WhisperKit + диаризация на CoreML.
- **В облаке:** быстрее и обычно точнее, деление по спикерам «из коробки», платно за минуты.
  Кандидатов (Russian + диаризация) сравнить на прототипе.
- Для «Кратко», «Протокола» и задач у пользователя есть API к облачному **Qwen 3.6** — основной кандидат
  на пилоте. В коде — любой OpenAI-совместимый адрес + модель + ключ (ключ только в локальном `.env`, не в git).
- «Кратко», «Протокол» и задачи — скорее всего ИИ через интернет (например, Claude API) в обоих режимах:
  локальные модели на телефоне пока слабо делают протоколы на русском. Проверить на прототипе.

- Облачный сервис в настройках — **свой адрес + ключ**, а не один зашитый провайдер. У пользователя есть
  доступ к API Whisper, развёрнутому на работе, — кандидат для облачного режима (уточнить: совместим ли с
  OpenAI API, есть ли деление по спикерам, можно ли по правилам работы отправлять туда свои записи).

## После пилота — масштабирование
Цель: закупить партию таких диктофонов для сотрудников и раздать наше приложение. Что из этого следует:
- Приложение ставится **на телефоны** сотрудников, диктофоны остаются как есть (их прошивку не трогаем).
- Раздача приложения: TestFlight на пилоте; потом App Store (скрытая ссылка) или корпоративное распространение
  через Apple Business Manager / MDM. Нужен Apple Developer аккаунт (лучше на организацию).
- Настройки (адрес рабочего Whisper, ключи) — заранее прописывать централизованно, а не вводить вручную.
- Bluetooth становится обязательным: массовым пользователям кабель неудобен.
- Привязка «телефон ↔ свой диктофон» по ID устройства.
- Риски: производитель может поменять прошивку или модель → закупать одну партию и проверять каждую новую;
  зависимость от OEM-устройства; согласовать с юристами работы обработку записей встреч и разбор протокола.
- Нужны **iPhone и Android** → одно приложение на общем коде. Предварительный выбор: **Flutter**
  (BLE — flutter_blue_plus; расшифровка на телефоне — whisper.cpp; PDF — пакет pdf). Альтернатива — Kotlin Multiplatform.
  Пилот всё равно ведём на iPhone пользователя, Android проверяем на тестовом телефоне.
- Android упрощает разбор Bluetooth: на нём можно включить запись Bluetooth-трафика (HCI snoop log) без Xcode.
