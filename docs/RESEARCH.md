# Исследование диктофона AIREC

## Устройство
- AliExpress: ALiandream «Цифровой диктофон», вариант «NEW AI VOICE RECORDER», 16 ГБ
  https://aliexpress.ru/item/1005009304093292.html
- Форм-фактор «карточка» 86×55×3.5 мм, OEM-устройство (вероятно, продаётся под разными брендами)
- Родное приложение: **AIREC** (AIREC LLC)
  - Android: `com.record.airec.google`
  - iOS: https://apps.apple.com/ru/app/airec/id6737178340 (id6737178340). Сборка из App Store зашифрована (FairPlay),
    поэтому для разбора протокола удобнее Android APK.
- Передача записей на телефон — по Bluetooth (скорее всего BLE). Транскрипция/саммари — вероятно, в облаке производителя.

## Окружение пользователя
- Телефон: iPhone
- Компьютер: MacBook Air (Apple Silicon)

## Цель
Своё приложение, которое забирает записи с диктофона и делает нормальную
транскрипцию/саммари (облачный «ИИ» производителя заменяем своим).

## План разбора протокола
1. [x] Проверить USB: виден ли диктофон как флешка (USB Mass Storage) и в каком формате файлы. См. «Результаты USB».
2. [x] BLE-скан с Mac (`bleak`): имя устройства, сервисы, характеристики, их свойства. См. «Результаты BLE-разведки».
3. [ ] Декомпиляция APK (`jadx`): UUID, команды, формат пакетов, кодек аудио, API-серверы.
   - Скачать APK из облачного контейнера не удалось (APKPure → 403), нужно скачать вручную в браузере.
4. [ ] Снять трафик родного приложения iPhone ↔ диктофон через PacketLogger
   (Xcode Additional Tools + профиль Bluetooth logging от Apple на iPhone).
5. [ ] Написать PoC на Python: подключиться, получить список файлов, скачать запись, декодировать аудио.
6. [ ] Решить стек приложения (iOS: Swift/CoreBluetooth или Flutter) и пайплайн ИИ (Whisper/LLM).

## Результаты BLE-разведки (2026-11-21)
Дамп: [`captures/gatt_127825C6-D4DC-DE94-6F2F-99E653A6A6F8.txt`](../captures/gatt_127825C6-D4DC-DE94-6F2F-99E653A6A6F8.txt)

### Реклама
- Имя: `AIREC(BLE)`; на этом Mac UUID `127825C6-D4DC-DE94-6F2F-99E653A6A6F8` (CoreBluetooth-UUID, на другом компьютере будет другим).
- Объявляемые service UUID: `0000af47-…`, `0137735a-…`, `00897178-…` (база `-0000-1000-8000-00805f9b34fb`).
  В GATT-таблице их нет — вероятно, в них закодированы данные (ID/MAC/статус), а не реальные сервисы. Проверить по APK.
- Manufacturer data нет.

### GATT
Один кастомный сервис `0011200a-2233-4455-6677-8899dfdedddc`
(стандартные Generic Access / Device Information macOS не показывает):

| Характеристика | handle | Свойства | Гипотеза |
|---|---|---|---|
| `0011201a-2233-4455-6677-8899dfdedddc` | 9  | notify | ответы / события |
| `0011202a-2233-4455-6677-8899dfdedddc` | 12 | write-without-response | команды |
| `0011203a-2233-4455-6677-8899dfdedddc` | 14 | notify | поток данных (аудио/файлы?) |
| `0011204a-2233-4455-6677-8899dfdedddc` | 17 | notify, write-without-response | двунаправленный канал (управление передачей?) |
| `0011206a-2233-4455-6677-8899dfdedddc` | 20 | write-without-response | ещё один канал записи |

- Читаемых характеристик нет; за 10 с подписки на все notify устройство ничего не прислало →
  протокол «команда → ответ», нужны байт-коды команд (шаги 3–4). Наугад в write-характеристики не писать
  (риск стереть записи / сбросить устройство).

### Заметки по запуску на macOS
- Из процесса без Bluetooth-разрешения (например, из Claude Code) Python падает с SIGABRT (TCC:
  нет `NSBluetoothAlwaysUsageDescription`). Запускать из Terminal.app, разрешив ему Bluetooth.
- Первый запуск сразу после запроса разрешения может дать `BleakError: Bluetooth device is turned off` — просто повторить.
- Системный Python 3.9 + pip 21 не ставит `pyobjc-core`; помогает `pip install --upgrade pip` внутри venv.

## Результаты USB (2026-11-21)
- По USB диктофон — обычная флешка (USB Mass Storage): media name `UDISK`, 15.6 ГБ, FAT32, метка `NO NAME`.
  Монтируется на macOS сам, без драйверов. В дереве USB рядом виден `USB Composite Device`.
- Содержимое:
  - `RECORD/ГГГГММДДччммсс.ops` — записи, имя = дата и время начала. Даты в FAT у файлов битые (2047 год).
  - `SET.bin` — 512 байт, похоже на зашифрованные/обфусцированные настройки (114 разных байт, повторяющийся «хвост» с периодом ~10 байт).
  - `System Volume Information/` — служебная папка Windows.
- Формат `.ops` — **сырые пакеты Opus без контейнера** (не Ogg: заголовка `OggS`/`OpusHead` нет). Разобран:
  - Файл — подряд идущие слоты по **80 байт**, общего заголовка нет. Каждый слот = один пакет Opus.
  - Первый байт — Opus TOC: `0x4b` = config 9 (SILK wideband, 16 кГц, 20 мс), моно, code 3;
    `0x48` = то же, code 0 (один кадр на весь слот).
  - При code 3 второй байт — счётчик кадров: `0x41` = 1 кадр + есть добивка, тогда третий байт = длина
    нулевой добивки в конце слота; `0x01` = 1 кадр без добивки. «KA» в начале — просто `4b 41`, не сигнатура.
  - 80 байт × 50 пакетов/с = **32 кбит/с CBR**. Размер файла всегда = 512·k − 64, последний слот бывает обрезан.
  - Проверка: libopus декодирует все пакеты без ошибок; 92% энергии в 300–3000 Гц, выше 8 кГц почти ничего —
    это речь. Длительности совпадают с интервалами между временем в именах файлов.
  - Шифрования нет. `SET.bin` пока не разобран.
- Конвертер: `tools/ops2wav.py` (PyAV/libopus) → WAV 16 кГц моно — сразу подходит для Whisper.
  ```
  .venv/bin/python tools/ops2wav.py -o captures/wav "/Volumes/NO NAME/RECORD"
  ```
- Вывод: записи можно забирать по кабелю и расшифровывать без Bluetooth и без приложения производителя.
  BLE нужен только для передачи без кабеля — его протокол (шаги 3–4) можно отложить.

## Настройки устройства (экран «My device» в AIREC, 2026-11-21)
SN `204112260900748`. Подключение в AIREC: Bluetooth или **Wired (OTG)** — значит, кабель к iPhone поддерживается.

| Настройка | Значение сейчас | Заметка |
|---|---|---|
| Segmented recordings | 1 час | длинная запись режется на файлы |
| Button to start | Recordings only | что делает кнопка при подключении к приложению |
| Idle shutdown | 30 мин | автовыключение |
| Microphone gain | 3 | усиление микрофона; при громкой речи вблизи есть клиппинг (0 dBFS) |
| Space management | 14.89 / 16 ГБ свободно | |
| Disk formatting | — | стирает все записи |
| Hide recordings | выкл | |
| Incoming calls are automatically recorded | вкл | запись звонков (диктофон крепится к телефону) |
| USB support | вкл | режим флешки — **не выключать**, иначе пропадёт доступ по кабелю |
| Boot recording | вкл | запись стартует при включении → вероятная причина потери первых 2–4 с |
| Automatic transfer | выкл | |
| Decibel detection | выкл | запись по голосу (VOX) |

- Настройки индикатора (светодиода) **нет** → менять только через прошивку или заказной прошивкой у производителя.
- Проверено: настройки **не** хранятся в `SET.bin`. После включения «Decibel detection» в AIREC файл не изменился
  ни на байт (и совпадает с копией от 17:36). Значит, настройки живут во внутренней памяти и меняются только
  командами по Bluetooth → управление настройками — часть разбора BLE-протокола.
  `SET.bin`, вероятно, постоянные данные устройства (идентификатор/ключ).
